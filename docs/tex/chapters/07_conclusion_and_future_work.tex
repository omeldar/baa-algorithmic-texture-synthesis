\section{Conclusion}

This thesis investigated how algorithmic texture synthesis methods can be used in a procedural real-time environment. For this purpose, a custom prototype was implemented that combines a texture synthesis laboratory with a procedurally generated 3D terrain environment. This allowed generated textures to be parameterized, applied to a real-time scene, and evaluated under controlled conditions.

The results show that procedural texture generation is the most suitable approach for the selected real-time use case. Procedural methods provide controllable visual variation with relatively low runtime cost. Rule-based methods are also useful for structured patterns such as cellular or crack-like textures, but their suitability depends strongly on the concrete algorithm and its complexity.

The performance evaluation showed that the prototype runs interactively on suitable desktop hardware, while more demanding configurations are not suitable for very weak laptop hardware. This confirms that browser-based procedural rendering is feasible, but still depends strongly on \gls{gpu} performance and scene complexity.

Optimization-based approximation was investigated separately. It can help estimate useful parameters for approximating a target texture, but it is too slow for direct real-time generation in the current prototype. It is therefore better suited as an offline or pre-processing step.

Overall, the prototype demonstrates that algorithmic texture synthesis can support controllable variation in procedural real-time environments. The work is not a production-ready material system, but it provides practical insight into the strengths and limitations of procedural, rule-based, and optimization-supported texture synthesis.

\section{Future Work}

Future work should focus on extending the number and quality of available texture models. More material categories, such as stone, soil, bark, fabric, or metal, would allow a broader comparison of algorithmic texture synthesis methods. More advanced rule-based models could also be added to better evaluate structured and semi-structured textures.

Another important direction is the improvement of visual quality metrics. The current evaluation relies mainly on runtime measurements and visual inspection. Future work could include more objective image similarity metrics, perceptual comparison methods, or user studies. This would make it easier to evaluate not only how fast a method is, but also how convincing and useful the generated texture is.

Further work could also improve optimization-based approximation. More efficient search strategies, better similarity metrics, and method-specific parameter spaces could make target texture approximation more useful. Since optimization is not real-time feasible in the current form, it would be most suitable as an offline process for generating presets that can later be used in the real-time environment.

Finally, the prototype could be tested on a wider range of hardware and browser environments. This would make the performance conclusions more general and help identify which parts of the system are limited by the implementation, the browser, or the \gls{gpu} hardware.

\section{Personal Reflection}

During the project, one of the biggest practical challenges was the evaluation effort. The final evaluation produced more than 240 test files, which took significantly longer to record, organize, aggregate, and analyze than expected. This showed that the implementation of an evaluation infrastructure is only one part of the work. The actual execution and interpretation of repeated test runs can become a large task on its own. In retrospect, more time should have been reserved specifically for evaluation preparation, data cleaning, and result validation.

Another important lesson was the value of early scoping. Some parts of the project, especially the implementation of example-based methods, required considerable effort but were less central to the final real-time evaluation. A short preliminary study before the start of the bachelor thesis could have helped identify earlier which approaches were most relevant for the final research focus. This may have reduced unnecessary implementation work and allowed more time to be spent on the core prototype, the real-time experiments, and the evaluation.

Overall, the project showed that a research prototype can change direction as technical limitations and evaluation results become clearer. The initial topic was broad, but the work gradually focused more strongly on real-time applicability, controllability, and reproducible measurement. This focus made the final evaluation more coherent and helped answer the research questions more clearly.
