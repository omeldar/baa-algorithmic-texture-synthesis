## Procedural Generation

> Content is generated by an algorithm (a procedure), usually based on mathematical functions.

We define a function, and the function computes the result automatically.

There are no explicit “if this, then that” symbolic rules — instead, the result emerges from formulas.

### Simple Example:

![Simple Procedural Example: Grayscale](/assets/experiments/initial_exploration/grayscale.png)

```py
for x in range(width):
    for y in range(height):
        value = sin(x * 0.1) * cos(y * 0.1)
        image[x, y] = value
```

This would generate a grayscale texture. Here:

- The texture is generated purely by a mathematical function
- No logical rules.
- Just computation.

### Visual example: Stripes

![Visual Procedural Example: Stripes](/assets/experiments/initial_exploration/stripes.png)

```py
if sin(x * 0.2) > 0:
    color = white
else:
    color = black
```

The pattern emerges from a mathematical wave function.

## Rule-Based Generation

> Content is generated by applying explicit rules or logical decisions.

Instead of computing values from formulas, we define symbolic rules. These rules describe structure, not just numbers.

### Simple Example

Rule:

- Every second tile is black
- Every third row is red

![Simple Rule-Based Example](/assets/experiments/initial_exploration/simple_rulebased.png)

```py
if x % 2 == 0:
    color = black
elif y % 3 == 0:
    color = red
else:
    color = white
```

### Visual Example: L-System (Tree)

![Visual Rules-Based Example: L-Systen (Tree)](/assets/experiments/initial_exploration/tree.png)

The rule looks like this:

```py
F → F[+F]F[-F]F
```

This is a rewriting rule. Each iteration replaces symbols based on rules. That is rule-basd generation.

## Optimization-Based Generation

> The texture is generated by solving an optimization problem.

Unlike procedural or rule-based methods, optimization based texture synthesis does not define a direct formula or symbolic rules. Instead, the texture emrges as the solution of a constrained optimization process. The image itsel fbecomes the optimization variable.

A common classical approach is matching statistical properties of a target texture. The generated image is iteratively modified so that its statistics (e.g. histogramm, mean, variance) approximate those of the target image.

### Simple Idea - Core Idea

We start with random noise, then iteratively enforce statistical constraints and finally minimize deviation between generated and target statistics. The final texture emerges as the solution of this optimization progress.

### Visual Example: Histogram Matching

The crucial part that makes this optimization-based is the iterative refinement loop:

```py
for i in range(iterations):

    # Match histogram to target
    generated = match_histogram(generated, target)

    # Enforce smoothness constraint
    generated = gaussian_filter(generated, sigma=smooth_sigma)
```

## Core Differences

| Aspect               | Procedural                        | Rule-Based                         | Optimization-Based                                   |
| -------------------- | --------------------------------- | ---------------------------------- | ---------------------------------------------------- |
| Generation Principle | Closed-form mathematical function | Symbolic rewriting / logical rules | Solve constrained optimization problem               |
| Control Mechanism    | Parameters of formula             | Explicit structural rules          | Statistical or energy-based constraints              |
| Structure Origin     | Directly defined by formula       | Constructed via rule application   | Emerges through iterative minimization               |
| Computation Style    | Single-pass evaluation            | Single-pass evaluation             | Iterative refinement process                         |
| Typical Output       | Smooth, continuous patterns       | Structured, discrete arrangements  | Statistically consistent, constraint-driven textures |
